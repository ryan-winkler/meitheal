# ADHD/Productivity Panel - Phase 04.3 Docs Narrative Iteration 01

## 15 ADHD/Productivity Lenses

| Lens | Recommendation | Decision |
|---|---|---|
| Scanability lens | Group features by jobs like capture, plan, work, sync, and handoff | Accept |
| Working-memory lens | Explain Grocy vs Meitheal in one memorable contrast instead of repeating it across sections | Accept |
| Decision-fatigue lens | Keep install and voice setup short and specific | Accept |
| Orientation lens | Add a simple vocabulary section so readers do not get lost between new and legacy terms | Accept |
| Confidence lens | Be explicit where counts differ by surface so readers do not feel tricked | Accept |
| Story lens | Use the home/homelab narrative to make the feature set feel connected | Accept |
| Deep-link lens | Point readers to the right doc for setup, protocols, and troubleshooting from the README | Accept |
| Friction lens | Keep machine-readable docs structured and skimmable for agents and tinkerers | Accept |
| Recovery lens | Surface exports, backups, and offline behavior as trust-building capabilities | Accept |
| Time-to-value lens | Highlight quick capture, Today, dashboard, and Assist early in the story | Accept |
| Mobile context lens | Mention companion handoff and PWA installability where users already think about availability | Accept |
| Terminology lens | Use compatibility notes instead of burying legacy vocabulary or over-explaining it | Accept |
| Visual chunking lens | Refresh screenshots to match the new story and reduce cognitive mismatch | Accept |
| Maintenance lens | Create canonical planning artifacts so the next docs refresh starts from context, not memory | Accept |
| Agent lens | Keep the skill docs aligned with the public story so external agents inherit the same framing | Accept |
