# ADHD/Productivity Panel - Phase 08.1 Settings UX Iteration 01

## 15 ADHD/Productivity Lenses

| Lens | Recommendation | Decision |
|---|---|---|
| Friction lens | Put the most-used personal controls before shortcuts and troubleshooting | Accept |
| Working-memory lens | Show common-task chips in section intros so users do not need to infer what belongs where | Accept |
| Reset/recovery lens | Add a visible search clear button and `Esc` behavior | Accept |
| Focus lens | Keep the summary strip visible while drilling into a section | Accept |
| Decision-fatigue lens | Reframe App/PWA around recommended paths instead of forcing users to self-assemble them | Accept |
| Mobile context-switch lens | Provide one obvious quick-jump surface on narrow screens | Accept |
| Error-prevention lens | Keep destructive actions isolated and introduce explicit consequence framing | Accept |
| Search trust lens | Label results as `Section` or `Setting` to reduce accidental jumps | Accept |
| Orientation lens | Use a “Settings Home” return action plus persistent rail on desktop | Accept |
| Time-to-task lens | Put backup/recovery, installability, and companion actions near the top of App/PWA | Accept |
| Visual chunking lens | Use shared cards and callouts to reduce the feeling of a long undifferentiated wall | Accept |
| Keyboard lens | Support arrow navigation in results before jump | Accept |
| Resilience lens | Keep navigation state synchronized even when jumps avoid `hashchange` | Accept |
| Habit lens | Keep frequent actions and summaries consistent across desktop and mobile | Accept |
| Confidence lens | Update KCS docs so the UI language matches the troubleshooting path users now see | Accept |
