# Phase 08.1: Settings UI/UX Polish — Research

**Researched:** 2026-03-15  
**Scope:** Settings shell IA, search, section presentation, App/PWA trust surfaces  
**Confidence:** High

## Current State

1. Phase 08 already replaced the tab stack with a searchable shell, but the shell still repeated section meaning across the summary strip, rail, and section intros.
2. Search could jump to anchors, but the result list lacked stronger task framing, keyboard navigation, and a visible reset affordance.
3. Mobile navigation reused the desktop rail pattern too literally, so it read as a compressed list rather than an intentional quick-jump control surface.
4. `SettingsGeneral.astro`, `SettingsSystem.astro`, and `SettingsIntegrations.astro` still contained repeated card, callout, and disclosure markup.
5. App/PWA and Danger Zone flows worked, but the guidance/trust surfaces still felt more “raw controls” than “guided product UX”.

## Key UX Gaps

1. Affordance clarity: summary cards and rail items needed clearer role separation.
2. Information hierarchy: section intros repeated copy instead of orienting the user around common jobs.
3. Search recovery: users needed a fast clear/reset path and cleaner keyboard-driven jumping.
4. Mobile ergonomics: section switching needed a compact quick-jump treatment instead of desktop-card shrinkage.
5. Consistency: repeated header/action/callout/disclosure patterns increased visual noise and maintenance cost.

## Recommended Direction

1. Extend `settings-registry.ts` with UI-only metadata so summary, rail, and section intros can each do a different job from one source of truth.
2. Add shared settings primitives for section intros, cards, callouts, action rows, disclosures, and status chips.
3. Keep the summary strip visible in detail mode so it stays the primary live-status and quick-jump surface.
4. Upgrade search with result metadata, arrow-key navigation, and a visible clear action.
5. Recompose Personal, App & PWA, Danger Zone, and parts of Workflow/Integrations around the new primitives without changing ids, endpoints, or persisted keys.
