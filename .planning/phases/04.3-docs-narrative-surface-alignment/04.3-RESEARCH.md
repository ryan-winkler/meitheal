# Phase 04.3: Docs Narrative & Surface Alignment — Research

**Researched:** 2026-03-19  
**Scope:** Public story, machine-readable docs, add-on docs, protocol docs, and supporting planning artifacts  
**Confidence:** High

## Current State

1. The root `README.md` still reflects an older product story and uses brittle feature-count language in places where the shipped surfaces have diverged.
2. Public machine-readable docs drift by surface today: Astro MCP exposes 18 tools, the Home Assistant custom-component MCP surface exposes 16 tools, and the Home Assistant LLM API exposes 21 tools.
3. The codebase already carries the newer DDD language in ADR-007, `packages/domain-tasks`, goals/projects routes, and hierarchy UI, but legacy `task_type`, Epic/Story, and board terminology still appear in compatibility and transition surfaces.
4. Add-on docs, custom-component docs, `WEBMCP.md`, skill docs, and duplicated `llms` assets all describe overlapping capabilities with inconsistent counts, routes, and maturity notes.
5. The current README screenshots do not tell the newer dashboard/settings/story clearly enough for a first-time reader.

## Key Gaps

1. Narrative gap: the docs describe features, but not the product arc from household capture to coordinated follow-through inside Home Assistant.
2. Terminology gap: the repo has both canonical and compatibility language, but the current docs do not explain that transition cleanly.
3. Surface gap: multiple AI/agent surfaces exist, yet current docs flatten them into one capability story and introduce count drift.
4. Asset gap: there are duplicated `public/` and `apps/web/public/` LLM docs, which makes drift easy unless they are updated together.
5. Planning gap: this repo expects KCS/planning rigor, but the docs refresh did not yet have its own canonical phase or persona-loop artifacts.

## Recommended Direction

1. Rewrite README around user jobs and product identity first, then let feature depth live in linked docs and machine-readable references.
2. Split machine-facing capability descriptions by surface: Astro app, HA custom component, HA LLM API, A2A, and experimental WebMCP.
3. Use a transitional vocabulary note anywhere a non-developer reader would otherwise be confused by both new and legacy terms.
4. Refresh identity sections of `AGENTS.md` and skill docs so contributors and agents inherit the same product framing without changing enforcement rules.
5. Capture the pass formally in `.planning/phases/04.3-*` and `.planning/persona-loops/phase-04.3/iteration-01/`.
