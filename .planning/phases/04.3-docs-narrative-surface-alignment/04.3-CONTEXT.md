# Phase 04.3 Context: Docs Narrative & Surface Alignment

## Domain Boundary

This phase updates Meitheal's public and machine-readable documentation so it matches the current product surface, Home Assistant story, and transitional DDD language. It does not change runtime behavior, schemas, routes, or add-on configuration.

## Decisions

1. Lead the story with Meitheal as a Home Assistant-native household and homelab execution hub for non-developer tech enthusiasts.
2. Organize public docs around real user jobs instead of a flat feature inventory.
3. Treat `Area → Goal → Project → Task → Routine` as the canonical vocabulary while explicitly calling out legacy `task_type`, Epic/Story, board, and Vikunja compatibility surfaces where they still appear.
4. Describe capability counts by surface instead of forcing one shared number across Astro MCP, the HA custom-component MCP server, and the HA LLM API.
5. Include formal planning and persona-loop artifacts in the same change set so the docs refresh is repeatable.

3. How much detail to include in machine-readable docs before linking deeper supporting docs.
4. Which codebase-map documents need targeted updates for this documentation pass.

## Deferred Ideas

2. Runtime protocol consolidation between Astro MCP and the HA custom-component MCP server.
3. Deeper KCS refactors outside the protocol/setup/storytelling docs touched by this pass.
