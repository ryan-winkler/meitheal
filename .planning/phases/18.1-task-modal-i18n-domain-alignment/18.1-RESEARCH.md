# Research: Task Modal i18n & Domain Alignment

**Phase:** 18.1

## Codebase Analysis

### Domain Model (`TaskKind` enum)
From `packages/domain-tasks/src/domain-model.ts`:
- `standard_action` — regular task
- `shopping_item` — shopping list entry
- `checklist` — checklist item
- `routine_instance` — habit/routine (created from templates, not user-selectable in modal)
- `quick_capture` — inline quick add (not modal-selectable)
- `calendar_event` — calendar-linked event

### Current Modal State
- `data-kind` values: `task`, `shopping_list`, `checklist`, `event` — **mismatch** with domain enum
- Hidden input sends `task_kind: task` — should be `standard_action`
- Templates button: **removed** in Phase 18 iteration but hardcoded strings remain
- 40+ hardcoded English strings in the Astro template
- CSS uses `border-white/5`, `border-white/10` — should use `border-border`, `border-border-dim`

### i18n System
- `t(key, locale, params)` accepts dot-notation, e.g. `t("task_modal.kind_task", locale)`
- Flat key lookup attempted first, then nested traversal
- Fallback to `en` if key missing in target locale
- `{param}` interpolation supported

### Theme System
- `_tokens.css` defines `--color-border`, `--color-border-dim`, `--color-bg-primary`, etc.
- Tailwind maps to: `border-border`, `border-border-dim`, `bg-bg-primary`, `text-text-muted`
- Dark, Light, Auto, HA-ingress themes supported
