# Phase 12 Plan 01: Modal P0-P9 Optimization Sweep

## Objective

Eliminate all remaining P0-P9 quality issues across the 3 modal files (`_modal.css`, `TaskDetailModal.astro`, `NewTaskModal.astro`). This covers emoji inconsistency, CSS indentation, inline style anti-patterns, and the `window.location.reload()` anti-pattern.

## Context

Previous GSD persona loop (iteration-01) addressed T1-T9 (stale CSS, hidden class, noscript fallback, save indicator guard, etc.). This plan catches the remaining items discovered during the P0-P9 deep scan.

## Scope Boundary

**In scope:** Emoji→SVG, CSS indentation, inline style cleanup (static elements only), reload anti-pattern.

**Out of scope:** The ~35 `style.display` toggles for transient dropdown/search-result UI in `task-modal-controller.ts` — these are correct imperative toggles for rapidly-shown/hidden elements. Migrating them to `hidden` class would add risk with no UX benefit. Also out of scope: D1 (auto-expand sidebar on mobile).

<task id="3" type="auto">
<name>Replace window.location.reload() with CustomEvent dispatch in NewTaskModal</name>
<files>
- apps/web/src/components/tasks/NewTaskModal.astro (line 443)
</files>
<action>
Replace `window.location.reload()` on successful task creation with:
```typescript
document.dispatchEvent(new CustomEvent("meitheal:tasks-changed", { detail: { action: "created" } }))
```
This allows list views (kanban, table, today) to listen and refresh without a full page reload. All existing views already handle `astro:page-load` or can listen for this event. The page reload is a known anti-pattern per Phase 08.2 cleanup.
</action>

# Expected: no matches
</verify>
<done>NewTaskModal dispatches `meitheal:tasks-changed` event instead of full page reload</done>
</task>
