# Phase 14.1 Context: Habits Shell Rollout

## Domain Boundary

This phase applies the mature Settings/dashboard shell language to `/habits` without redefining the routines domain model, the `/api/habits` contract, or the underlying `TemplateRepository`.

## Decisions

1. Keep the user-facing page label as `Habits`, while preserving `routine` terminology in code and DDD-facing documentation.
2. Render the initial habits payload server-side through `TemplateRepository` so the page stays Astro-first and Home Assistant-friendly on first load.
3. Use `UnifiedBar` plus same-page hash anchors for the habits sections so navigation remains ingress-safe.
4. Replace the long inline page script with a lifecycle-safe controller and a small section registry instead of layering more behavior onto the old file.
5. Keep the existing `/api/habits` CRUD path as the only mutation surface.

3. Whether the create action lives in the unified bar only or also appears as an inline section action.
