# Phase 14.1: Habits Shell Rollout — Research

**Researched:** 2026-03-19  
**Scope:** Mature shell rollout for `/habits` after the dashboard proving slice  
**Confidence:** High

## Current State

1. `settings.astro` and `index.astro` already prove the unified shell pattern: `UnifiedBar`, hash anchors, SearchHub launch, and lifecycle-safe page boot paths.
2. `habits.astro` still owned a long inline script with raw event listeners, manual DOM rendering, and duplicated fetch logic.
3. `/api/habits` already uses `TemplateRepository`, so the routines data model is stable enough for an Astro-first page refresh.
4. The previous habits edit flow did not rehydrate description or priority from `template_json`, which meant updates could silently flatten those values.

## Key Gaps

1. Shell gap: habits did not expose a canonical section model or unified bar interaction contract.
2. Lifecycle gap: the inline script registered listeners directly and did not align with `pageLifecycle`.
3. Astro-first gap: the initial habits view was client-loaded instead of server-rendered.
4. UX gap: checklist items looked interactive even though the page only needed to show the template checklist state.

## Recommended Direction

1. Add a habits section registry and render `UnifiedBar` tabs for overview, rhythm, library, and cross-page flow.
2. Move habits page behavior into a lifecycle-safe controller that owns shell navigation plus habit CRUD orchestration.
3. Render the first habits payload server-side, then refresh from `/api/habits` after mutations.
4. Show checklist templates as read-only list items instead of fake checkboxes.
5. Queue the remaining rollout order as: Today, Upcoming, Calendar, Kanban, Table. The first three already have section-friendly narratives; Kanban and Table need denser toolbar-shell reconciliation.
