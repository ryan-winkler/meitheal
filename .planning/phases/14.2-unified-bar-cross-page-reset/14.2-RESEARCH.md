# Phase 14.2 Research: Unified Bar Cross-Page Reset

## Current State

1. Settings, Dashboard, and Habits already prove the mature shell language: sticky `UnifiedBar`, hash-linked sections, SearchHub launcher, and pageLifecycle-safe controllers.
2. Today already has an extracted controller and the strongest remaining single-page section narrative.
3. Upcoming and Calendar still own inline page scripts, so they cannot safely absorb the shell without extraction first.
4. Kanban and Table already have extracted controllers, but both pages are dense and still rely on a separate route-switch strip plus high-value contextual controls.
5. Home Assistant companion guidance still supports `homeassistant://navigate<PAGE_PATH>` and the same URL-handler actions through `x-callback-url`, which aligns with ingress-safe route and hash design.

## Key Risks

1. Flattening route switching and section switching into the same row would damage task-view context.
2. Migrating Upcoming and Calendar before controller extraction would reintroduce listener ownership problems.
3. Promoting dense customizer controls into shell actions would recreate the old cluttered topbar pattern.
4. Losing query-string preservation on task-view switches would break cross-view continuity.

## Recommended Direction

1. Add one reset phase for audit, synthesis, and backlog alignment.
2. Reuse a shared shell-helper layer for section state, keyboard movement, and companion-safe path building.
3. Preserve `TaskViewTabs.astro` as a second-row route switcher on Calendar, Kanban, and Table.
4. Use Overview and Flow sections to orient the user before dense lists, boards, grids, and fields.
5. Close the program with Tier 2 HA verification even if each page slice is primarily Tier 1 code.
