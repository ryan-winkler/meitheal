# Phase 08.2 — Settings Controller Decomposition: Research

**Date:** 2026-03-16
**Prior phases:** 08 (Settings Redesign), 08.1 (Settings UX Polish)

## Problem Statement

`settings-controller.ts` is a 3,561-line single-function monolith (`initSettingsController()`) containing 25+ named sub-functions and 60+ event listeners. It violates DDD by mixing 7 domain concerns into one file:

1. **Theme/Appearance** — theme select, custom CSS upload/sanitization
2. **Sidebar/Navigation** — drag-drop ordering, custom links, visibility
3. **Integrations** — HA connection, calendar sync, todo sync, Grocy, n8n, Node-RED, webhooks, HA Bus
4. **AI/Agents** — AI provider, conversation agent, protocol toggles
5. **Data/Export** — JSON export, SQLite download, settings import, custom fields
6. **Workflow** — framework mapping, labels, notifications
7. **Danger Zone** — purge, reset, factory reset

## Anti-Pattern Inventory

| Pattern | Count | Severity |
|---------|-------|----------|
| `window.location.reload()` | 6 | High — forces full page refresh instead of reactive update |
| Inline `.style.*` mutations | 154 | Medium — should use CSS class toggles |
| Raw `fetch()` with manual ingress prefix | 8 | Medium — Layout.astro monkey-patch already handles this |
| `innerHTML` with dynamic data | 5 | Medium — XSS risk, `escapeHtml()` already available |
| `(window as any)` cast | 2 | Low — `global.d.ts` should cover these |

## Existing Architecture (Good)

Phase 08/08.1 already delivered clean separation for:
- `settings-registry.ts` (341 LoC) — section/field metadata, search
- `settings-shell-controller.ts` (471 LoC) — shell nav, search, intersection tracking
- `settings-store.ts` (58 LoC) — settings API client
- `settings-page.ts` (20 LoC) — page lifecycle bootstrap

These files are well-structured and need no changes.

## Test Coverage

- `settings-shell.spec.ts` (141 LoC) — 8 tests: search, summary cards, keyboard nav, deep links, mobile
- `theme-settings.spec.ts` (103 LoC) — theme persistence, custom theme
- `agent-protocol-settings.spec.ts` (56 LoC) — protocol toggle persistence

**Gaps:** No e2e coverage for sidebar config, integrations, data export/import, or danger zone.

## Decomposition Strategy

Split by **settings-registry.ts section boundaries** — each domain-aligned controller maps to exactly one registry section. This ensures:
- Controller boundaries match navigation boundaries
- Search results resolve to the correct controller
- Future lazy-loading can load controllers per-section

## Risk Assessment

- **LOW:** Controller split is purely structural — public API (`initSettingsController`) stays the same
- **MEDIUM:** Removing `window.location.reload()` requires careful verification that all state propagates
- **LOW:** Astro component splits (Phase 3) are optional and can be deferred
