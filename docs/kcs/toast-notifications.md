# Toast notifications

Meitheal renders transient status toasts, transactional Undo/Retry prompts, and persistent notifications (such as Service Worker update prompts—often called "growlers", implemented here as `persistent: true` toasts rather than a separate component) through a single `<ToastRegion />` (`#toast-container`) mounted once in `apps/web/src/layouts/Layout.astro` and controlled by `apps/web/src/lib/toast.ts`. The separate top-right PWA install banner (`apps/web/src/components/pwa/PwaInstallBanner.astro`, `role="complementary"`) shares `apps/web/src/lib/swipe-dismiss.ts` and `.btn` / `.pwa-banner__dismiss` styling but intentionally mounts outside `#toast-container` under the legacy `toast.pwa_install_*` i18n keys.

## Architecture and contracts

- **Single root mount**: `apps/web/src/components/ui/ToastRegion.astro` carries `transition:persist="toast-container"` so `#toast-container` survives Astro `ClientRouter` transitions. Behind Home Assistant ingress, `Layout.astro` disables `ClientRouter` (`{!behindIngress && ...}`).
- **Unified API**: `pushToast()`, `showToast()`, `showUndoToast()`, `showRetryToast()`, `showTaskCreatedToast()`, and `dismissToast()` share one DOM builder (`initToastSystem()` exposes `window.showToast` and `window.__meithealToast`, bridges `meitheal:toast` / `meitheal:conflict-detected`, and drains pre-hydration `window.__meithealToastQueue` calls at boot).
- **Tabler alignment & SVG sprite coupling**: Surfaces, semantic borders (`--success`, `--danger`, `--warning`, `--info`), and 1.75px outline SVG icons come from Meitheal design tokens (`apps/web/src/styles/_tokens.css`, `_feedback.css`) and `createSpriteIconElement` (`apps/web/src/generated/icon-registry.ts`, generated at build time from `@tabler/icons`). Canonical Tabler targets for dynamically created icons—including `ToastIconName` canonical targets (`"check"`, `"x"`, `"alert-triangle"` via `"warning"`, `"info-circle"` via `"info"`, `"refresh"`, `"bell"`) and `PwaInstallBanner`'s `"device-mobile"` (via `"phone"`)—must be listed in `CLIENT_DYNAMIC_TABLER_ICONS` inside `apps/web/scripts/generate-icons.mjs` (never legacy aliases directly, which fail codegen) so `<IconSpriteDefs />` emits their `<symbol>` on every route. Banner copy keys (`toast.pwa_install_*`) live in `apps/web/src/i18n/en.json` and `ga.json`.
- **Stable DOM slot order (`children[0]` / `children[1]`)**: Direct children of `.toast` keep `children[0]` as `.m-toast__icon` (hidden via `[hidden]` rather than removed when `icon: null`, with `-0.625rem` inline-start compensation across `.m-toast__message`, `.m-toast__description`, and `.m-toast__actions`) and `children[1]` as plain `.m-toast__message` text, preserving CSS Grid columns and E2E DOM observers.
- **Selective coalescing & callback lifecycle**: Rapid identical toasts coalesce via `data-repeat-count` (`::after` counter badge + `#sync-announcer` in `apps/web/src/layouts/Layout.astro`) **only** when `type !== "error"` and neither the existing nor incoming toast sets `id`, `action`, `persistent`, `description`, `dedupe: false`, `onDismiss`, `onAutoClose`, or `onForceCommit`. `"error"` notifications stay separate so repeated failures remain individually noticeable. `onDismiss` and `onAutoClose` are mutually exclusive: auto-dismiss invokes `onAutoClose`, whereas manual close, swipe, overflow eviction, and action clicks with `closeOnClick !== false` invoke `onDismiss`.
- **Locale resolution & cross-references**: `toast.ts` resolves single-argument `window.mI18n.get(key)` against the SSR-rendered locale catalog; cross-tab opposite-locale `localStorage` switching applies only to keys in `programmaticKeys` (`apps/web/src/i18n/translations.ts`). Keep translations parameterized via `.replace(...)` (e.g., `toast.created_task`). See [Client-Side Patterns](client-side-patterns.md#toast-system) for helper signatures and [PWA & Offline Guide](pwa-offline-guide.md) for banner/SW lifecycle details.

## Top Layer, overlay stacking & accessibility

- **Live region semantics**: `error` and `warning` toasts set `role="alert"` (`aria-live="assertive"` — relied on by existing E2E specs); `success` and `info` set `role="status"` (`aria-live="polite"`). `#toast-container` omits live-region attributes so assistive tech never encounters nested live regions, attaches `aria-label` only while non-empty so empty routes expose no empty region landmark, uses `#sync-announcer` (`Layout.astro`) for repeat-count and action progress announcements, and is excluded from blocking-modal scroll-lock/shortcut watchdogs (`Layout.astro` `isRealModalOpen()`, `hasPriorityOverlay()`, `apps/web/src/styles/_modal.css`).
- **Popover & blocking-modal ordering**: When visible, `#toast-container` receives `popover="manual"` and calls `showPopover()` (removed when empty), keeping `z-index: 10010` fallback above ordinary modals while blocking confirmation/prompt/Tabler modals (`dialog[open]`, `[data-meitheal-tabler-modal].show`, `#meitheal-confirm-overlay`, `#meitheal-prompt-overlay`) force `#toast-container` down to `z-index: 9998` and confirmation/prompt overlays sit at `z-index: 10020` (styled via `apps/web/src/styles/_feedback.css`) and promote unconditionally via `openManagedDialog()` (`apps/web/src/lib/dialog-overlay.ts`, which also centralizes `UNPROMOTED_BLOCKING_OVERLAY_SELECTOR`, `PRIORITY_OVERLAY_SELECTOR`, `findModalTrapTarget()`, `canRestoreFocusTarget()`, `dialogText()`, and `notifyOverlayChange()`). Three coupled guards maintain safe stacking and keyboard focus:
  1. `hasPriorityOverlay()` in `apps/web/src/lib/layout-shortcuts-controller.ts` checks `[popover]:popover-open:not(#toast-container)` so open toasts never disable global or Timeline shortcuts (`apps/web/src/lib/timeline-controller.ts`), while `findModalTrapTarget()` (called by `apps/web/src/lib/layout-controller.ts`) keeps `Tab` focus trapped back inside non-blocking modals (`#search-hub-overlay`, `#new-task-overlay`, `.habit-modal-overlay`, `#ask-ha-overlay`, and un-docked `#task-detail-overlay`) if a toast inside `#toast-container` receives focus.
  2. `apps/web/src/styles/_modal.css` hides `#shortcut-modal` when blocking or priority overlays (including `#search-hub-overlay:not(.hidden)` and `.habit-modal-overlay:not(.hidden)`) are open, while `apps/web/src/lib/dialog-overlay.ts` yields `Escape` from confirm/prompt overlays to focused `#toast-container` controls and `layout-shortcuts-controller.ts` lets plain `Escape`/`Enter`/`Space` activate focused toast controls while trapping `Tab` and blocking app shortcuts back into `#shortcut-modal`.
  3. `openManagedDialog()` and `openTablerModal()` (`apps/web/src/lib/tabler-modal.ts`) dispatch `meitheal:overlay-opened` / `meitheal:overlay-closed`, and `toast.ts` listens to those plus capture-phase `toggle` on `[popover]` so existing `:popover-open` toasts demote immediately when managed/Tabler/popover modals open. Native `dialog.showModal()` dialogs (`#framework-wizard-dialog`, `#fw-import-dialog`) layer above existing toasts natively (`UNPROMOTED_BLOCKING_OVERLAY_SELECTOR` `dialog[open]` prevents re-promoting new pushes while open), and a capture-phase `close` listener on `HTMLDialogElement` re-syncs and re-promotes when they close.

## Eviction, timers & mobile gestures

- **Eviction & cap (`MAX_ACTIVE_TOASTS = 5`)**: Pass 1 evicts oldest non-persistent, non-commit toast; Pass 2 evicts uncommitted `onForceCommit` items (`showUndoToast` with `onCommit`) if all 5 slots hold commits/persistent items; Pass 3 enforces the 5-item cap across persistent items.
- **Timers & `pagehide` / `astro:before-swap` commit**: Default auto-dismiss is `3500ms` (`success`, `info`), `4500ms` (`warning`), `5500ms` (`error`). Timers pause for hidden tabs (on creation and `visibilitychange`), focus, active drag, and mouse-only hover (`HOVER_PAUSE_MAX_MS = 6000ms` cap prevents a stationary cursor or missed `pointerleave` from keeping a toast pinned indefinitely), with a `1200ms` resume floor. Uncommitted `onForceCommit` callbacks flush synchronously once on `pagehide` and `astro:before-swap` and remove the toast (use `fetch(..., { keepalive: true })` for network commits).
- **Positioning & swipe-to-dismiss**: On desktop (`>= 1440px`), `body.has-docked-inspector` offsets `#toast-container` clear of the 420px inspector rail, and scoped CSS `:has()` rules on `body:has(...) .toast-container` (equal `(0, 3, 1)` specificity ordered by height) raise toasts above `.pomodoro-pill` and go-top buttons (`56px`; `:where(#settings-go-top)` avoids ID specificity inflation), `#bulk-bar` via `.bulk-bar[data-bulk-open="true"]` (`84px`), and `.pomodoro-panel` (`240px` panel width with `--toast-fab-clearance: 308px` on fine pointers and `340px` under `(min-width: 769px) and (pointer: coarse)` where 44px controls expand panel height; `transition:persist="pomodoro-timer"` lives on `#pomodoro-root` in `apps/web/src/components/pomodoro/PomodoroTimer.astro`, rendered conditionally in `Layout.astro` under `{!privatePageShell && showPomodoro && <PomodoroTimer />}`). At `<= 768px`, toasts span full safe-area width above `#mobile-tab-bar` (`--floating-action-bottom`) and flip via `data-dock-top="true"` as the single source of truth (`data-keyboard-open="true"` with non-additive `max(var(--toast-vv-top, 0px), env(safe-area-inset-top, 0px))` + scrollable `--toast-vv-max-h`, or when `.pomodoro-panel` is expanded on mobile via `meitheal:layout-changed`; `toast.ts` emits `meitheal:toast-dock-changed` when top-docked toast visibility changes—triggered by `meitheal:layout-changed` or viewport resize—so `PwaInstallBanner` suppresses via `visibility: hidden` without listener-order races). `apps/web/src/lib/swipe-dismiss.ts` implements bilateral 24px viewport edge guards, `lostpointercapture`/abort cleanup, and post-lock velocity flick detection (`0.35 px/ms`); `apps/web/src/styles/_feedback.css` and `_responsive.css` configure `touch-action: pan-y` on desktop (and on overflowing `[data-scrollable="true"]` top-docked stacks, where vertical swipe-dismiss yields to vertical touch scrolling) vs `touch-action: none` on `<= 768px` and top-docked viewports alongside `44×44px` dismiss and `44px` action targets under `@media (max-width: 768px), (pointer: coarse)`, while `toast.ts` synchronously removes the toast DOM node under `prefers-reduced-motion: reduce` and `PwaInstallBanner.astro` synchronously hides `#pwa-install-banner` in place (`display: none`) and cancels its timers.

## Timer lifecycle checks

When updating a toast from persistent to timed, synchronize both focus and document visibility pauses before starting its timer. To check this, update a persistent toast while the tab is hidden, wait longer than its duration, then return: it should remain until visible and then expire.

For the Pomodoro controller, an action response from a previous mount must not decrement the current mount's active action counter. Keep the generation check and positive-counter guard together in request cleanup.
